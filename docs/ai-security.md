# Optional AI: security, operation and integration

This is an implementation and verification guide, **not hosted acceptance evidence or a performance claim**. The new AI tests have to run on approved GitHub-hosted infrastructure with synthetic data. No real provider credentials, paid calls, private articles, production dumps or reference captures are needed.

## Application integration

`installAiRoutes` registers the configured AI worker and result-management endpoints. Migration 009 captures each job's model/configuration revision and creates selective history indexes. Startup applies it in the normal ordered migration sequence; never edit an already-applied checksum. The following describes the shipped integration and the regression gates used to validate it.

1. The API dependency lock includes `franc@6.2.0` (language detection) and `domhandler@5.0.3` (DOM node types). Preserve their upstream license notices.
2. Build shared types before API/web. `packages/shared/src/index.ts` exports `AiConfig`, `AiJob`, `AiResultSummary`, `AiOperation` and `AiLanguage` through `./ai.js`.
3. In `apps/api/src/app.ts`, import:
   ```ts
   import { AiService } from './ai.js';
   import { aiEnvironmentFromEnv } from './ai-security.js';
   import { installAiRoutes } from './ai-routes.js';
   ```
   After migration and **after `new Auth(...).install(...)`**, construct/register:
   ```ts
   const ai = new AiService(db, aiEnvironmentFromEnv());
   installAiRoutes(app, ai, { worker: config.worker });
   ```
   The optional third `AiService` argument is a synthetic provider seam for tests, not an alternate production transport. Do not accept it from HTTP input. `installAiRoutes` registers an `onReady` worker hook only when enabled, and a `preClose` hook that aborts/drains AI work **before** the existing application `onClose` closes PostgreSQL. For a separate worker process call `start()` and await `stop()` before `db.end()`. Do not register multiple AI services on the same Fastify instance.
4. Migration discovery already loads sorted `.sql` files. Apply additive `009_ai.sql` after the existing ordered migrations. It uses the existing `(articles.id, articles.user_id)` ownership constraint. No old migrations are edited. AI tables cascade with article/user deletion; no original content, annotations, retained contexts or blobs are updated by AI.
5. Keep the existing method-only request serializer, header redaction and sanitized global error handler. Do not enable request-body, SQL-parameter, raw provider response, or full request/TLS-error logging. The AI plugin adds its own safe error mapping and fatal UTF-8 JSON parser. Register after Auth so session, Origin and CSRF hooks are inherited, not replaced; its own missing-auth guard is additional defense, not a substitute for Auth.
6. The existing API `test/*.test.ts` execution glob includes the new source-named tests; no new package script is required. API `tsconfig.json` includes source only, and repository `tsconfig.tests.json` includes e2e only: explicitly typecheck the AI test sources too. Hosted CI must install the dependencies, build shared, typecheck API/tests, and run the API tests. The network/PG suites require `GITHUB_ACTIONS=true`, `RUNNER_ENVIRONMENT=github-hosted`; PG additionally needs a fresh synthetic `TEST_DATABASE_URL`. Never set these flags to bypass the infrastructure restriction locally. The HTTPS witness requires the repository's Node24 engine and `openssl` on the approved hosted runner; it generates a one-day synthetic certificate in an already existing `mkdtemp` root, restores Node's CA list and removes that root. New PG witnesses use SQL only, not Store/application filesystem startup; they do not manufacture counter rows or introduce a migration008.

## Private operator configuration

- `AI_ENCRYPTION_KEY`: canonical base64 encoding of **32 independently generated random bytes**. Missing or invalid values disable secret persistence/use, without failing RSS startup. There is no fallback to the session key, plaintext or an ephemeral key. Preserve this stable key with private deployment configuration and recovery material; never put it in this repository, CI output, public archives or the browser.
- `AI_ALLOW_HOSTS`: comma-separated exact lowercase hostnames or unbracketed IP literals, **not** URLs, wildcard suffixes, ports or user-controlled request fields. An invalid list disables all exceptions. This separate list does not inherit `FETCH_ALLOW_HOSTS`. Explicit exceptions can permit HTTP/private/loopback self-managed or CI providers. Without an exception the destination must be public HTTPS on port 443. Grant exceptions narrowly: allowing a hostname explicitly trusts that hostname's resolved addresses.

API credentials use AES-256-GCM, independent random 96-bit nonces, 128-bit tags and associated data `["feedink-ai-key",1,owner,configRevision]`. Changing metadata re-encrypts a retained credential under the new revision. Owner substitution, revision substitution, tampering, deployment-key loss or a changed encryption key fails closed. Omitted `apiKey` retains the authenticated old key; `null` clears it, including when the deployment key is unavailable. Replacing a credential does not require decrypting the old credential. Losing the stable deployment key requires explicitly saving new provider credentials; rotating the session secret does not.

`GET/PUT /api/ai/config` return **direct metadata**, never a key, envelope, nonce or credential hint. Defaults are `{enabled:false,baseUrl:"",model:"",hasKey:false,targetLanguage:"zh-CN",revision:0,updatedAt:null}`. One configuration row exists per account. Disabled metadata can be saved without a key; enabling requires URL, model and an authenticated stored key. All updates advance the revision. Demo accounts cannot configure AI or invoke connectivity/article work.

`POST /api/ai/config/test` uses the saved configuration (it may be disabled), makes one explicit JSON connectivity request and returns `{ok:true}`. It accepts no provider override and no article content. There is one process-local pending probe and one PostgreSQL advisory-locked probe globally. It never retries. It is not a public proxy.

## Transport and redaction

The production `PinnedAiProvider` is the only default transport. For each request it resolves the URL hostname, validates **all** returned addresses, then pins the socket lookup to an already validated address while retaining the URL Host/SNI and normal TLS certificate verification. No agent pooling, proxy environment transport, second DNS lookup, automatic SDK retries or alternate transport is used. Even same-origin redirects are refused; no redirect receives the authorization header or article body. DNS and HTTP share a 45-second deadline. Responses must be uncompressed JSON, HTTP 200, at most 512 KiB, exactly one completion, `finish_reason:"stop"`, no tool calls/refusal. Requests are at most 128 KiB with `max_tokens:8192` for article work and `max_tokens:16` for the connectivity probe. Unsupported JSON-mode providers fail safely rather than silently switching protocol.

Exceptions and job error DTOs use a fixed vocabulary. Provider bodies, Node/TLS/parser exception strings and SQL parameter details are never used as error messages or written to logs. Successful model content is parsed as schema-validated text, not returned as a raw completion envelope. Credential-reflection rejection checks serialized output **and decoded JSON string values**, then checks translations in source-segment order across batches and summary joins before another reduction call. The final publication transaction re-authenticates the job's admitted `config_revision` under the existing owner/source locks and checks result strings, entity-decoded visible HTML, separate original/translated text lanes, and translated `alt`/`title` metadata before binding any result to SQL. A newly changed configuration cannot substitute its credential for the admitted revision. Rejected content/key material is not added to the job, logs or error DTO; failure is the fixed `AI_OUTPUT`, with no automatic retry. Literal matching after these specific decodings/joins is deliberately conservative and may reject coincidental matches, especially with short keys. It does **not** claim detection of arbitrary deliberate secret encodings by a trusted provider. Do not attach full provider objects to telemetry; record only safe counts/status/codes if operational telemetry is added elsewhere.

## Source identity and browser contract

`POST /api/articles/:id/ai` accepts only `operation`, selected `mode`, optional `targetLanguage`, `force`, optional **expected** `contentHash`, and optional **expected** `configRevision`. The hash must match the current authoritative selected owned source or the request fails HTTP 409 before enqueueing or invoking a provider; it cannot replace source data. `configRevision` is an integer in 0..2147483647, never string-coerced. It is compared after the admission advisory lock and owner `FOR NO KEY UPDATE` lock, before key decryption, source acquisition, cache lookup or insertion. A mismatch returns HTTP409 `{error:{code:"AI_CONFIG_CHANGED",message:"The AI configuration changed; review it before requesting a new job"}}`; malformed values return `AI_REQUEST` (400). Absence remains API-compatible; browser requests must always send the configuration revision they reviewed, alongside the source hash.

`AiJob.configRevision: number` is **required** in every job DTO and comes directly from stored `config_revision`: new/admitted, active duplicate, cache, current polling, cancellation and historical retrieval all use that one mapper. A stale response-only DTO and explicit history retain the original revision, never the current settings revision. `AiResultSummary` listing metadata is unchanged. The existing `AI_INTERRUPTED` (409) rejection for a failed/cancelled matching job without `force:true` is unchanged; the browser must offer explicit paid-retry consent rather than silently resending.

`AiJob.contentHash` uses the existing `Annotations.currentContext` / `canonicalAnnotationHash` semantics, **not** the ingest `ArticleDetail.contentHash`. The cache additionally fingerprints title and exact selected stored HTML, so title/image-ID presentation changes do not reuse an old title-dependent result even if the portable canonical hash is unchanged. Keys include owner/article/mode/source fingerprint/operation/target/config revision/prompt version. Missing fulltext fails explicitly; it never falls back to feed content. The browser must keep its selected raw feed/fulltext view and original annotations separate, verify expected canonical context on explicit action, and fence polling/publication by account/auth epoch, article, mode and current source metadata. `result.sourceTitle/sourceUrl` describe the captured source, not model-generated metadata.

Bilingual output uses server-owned markers only:

```html
<section class="feedink-ai-pair">
  <div class="feedink-ai-source"><p>Original paragraph</p></div>
  <div class="feedink-ai-target" lang="zh-CN"><p>Translated paragraph</p></div>
</section>
```

Disclosure labels have a different, phrasing-only seam:

```html
<details>
  <summary><span class="feedink-ai-source">Original label</span><span class="feedink-ai-target" lang="zh-CN">Translated label</span></summary>
  <section class="feedink-ai-pair">…paragraph divs…</section>
</details>
```

Keep one direct-child `details > summary`. Its source/target spans are **inside** that summary; no section/div wraps or duplicates the control. Invalid extra source summary controls become ordinary paired content without discarding their text. Block descendants in labels are unwrapped to phrasing content. The web sanitizer must preserve only `span.feedink-ai-source` and `span.feedink-ai-target` on spans (optional valid `lang`), in addition to the existing paragraph markers on their exact tags. Do not permit arbitrary source classes.

Pairs are paragraph/inline-run level, not two whole-article blocks. Title, headings, lists, table-cell prose and captions are included. Original classes/IDs are stripped before adding markers; only the exact marker classes survive final sanitization. Link destinations and authenticated owned image references come exclusively from the trusted sanitized source. Text translations replace text/alt/title only and cannot create links, images, HTML or executable Markdown. The translated view carries no original ink/annotation positional anchors. Code/preformatted code is left unchanged by translation because programmatic tokens and formatting must not be localized; summary includes the code as source input. Render summary as plain text above the original selected body, never as HTML/Markdown.

## Permanent result history and explicit cleanup

Summaries, translations and other terminal job records persist long-term. There is **no automatic age, per-owner count or global count eviction**, no cache TTL, and no archive-wide retained-count work during admission or maintenance. Existing article/user deletion cascades remain unchanged. Capacity planning and backups must account for accumulated results; this does not add AI credentials/results to the old portable archive formats.

- `GET /api/ai/results?limit=20&cursor=...` returns `{items:AiResultSummary[],total:number,nextCursor:string|null}`. `limit` is 1..100. Items contain exactly `{id,articleId,sourceTitle,mode,contentHash,operation,targetLanguage,status,model,createdAt,updatedAt}` for owned terminal rows (`succeeded`, `skipped`, `failed`, `cancelled`). `model` is captured at enqueue, not read from the current configuration. Listing reads no source bodies, generated result bodies or credentials, and never contacts a provider.
- Ordering is immutable `created_at DESC,id DESC`. Opaque versioned cursors are owner-bound and preserve all six PostgreSQL fractional timestamp digits; timestamp text is bound through `::text::timestamptz`, not a JavaScript Date. The exact owned terminal total ignores the cursor and is read in the same repeatable-read snapshot as the metadata page. A subsequent page is a new snapshot: explicit cleanup or newly terminal jobs may change its total. The cursor is not authorization. Exact totals require scanning the matching owned terminal index entries; no constant-time or million-result latency is claimed.
- `GET /api/ai/results/:id` returns `{job: AiJob}` for an explicitly requested owned terminal record, regardless of later source/configuration/model/key changes. It returns the **original captured identity, metadata and exact saved output**, not the current article's identity. Missing, foreign or active IDs return the same safe 404. This endpoint is historical access only: never attach its old output or anchors to the current reader context. No new history-viewer UI is required by this API change.
- `GET /api/ai/jobs/:id` remains current-reader polling. A stale successful/skipped result is masked by a **response-only** failed/stale DTO without output. It does not erase stored terminal bytes, change persisted terminal status, or rewrite timestamps. Active stale work can still fail normally; cancelled/failed records remain terminal history. Historical access and current publication are deliberately distinct.
- `DELETE /api/ai/results` accepts only `{ids:string[]}`, 1..100 unique UUIDs. It locks and validates the complete selected owned set before deleting anything; any missing, foreign or active ID rejects the whole transaction with `AI_RESULT_SELECTION` (409). Malformed/duplicate/oversized selections fail 400. Success is HTTP 200 `{deleted:number}`. There is no delete-all shortcut, no cancellation side effect and no provider call. Original articles/images/notes/retained contexts and API credentials remain unchanged. All writes still require existing session/Origin/CSRF checks; demo accounts cannot list, retrieve or clean up AI history.
- `DELETE /api/ai/jobs/:id` remains explicit cancellation, **not** result cleanup. A cancelled/failed record can subsequently be selected for cleanup. In-flight workers only update rows with their live running lease; they never insert/upsert a missing job. Deleting a terminal row therefore cannot let a delayed provider response recreate the row or its result.
- After explicit cleanup, a later explicit article request may miss the saved result and require paid regeneration. Keep management inside AI settings, collapsed until opened; fetch metadata only after that user action, with pagination and explicit row selection. No idle-reader listing call. Confirm selection with wording such as: “Delete these saved AI results? Articles, notes and API settings are unchanged. Regenerating results may incur provider charges.” Browser regressions cover this interaction independently of API authorization tests.

## Durable queue, budgets and recovery

- Jobs are stored in PostgreSQL with queued/running/succeeded/skipped/failed/cancelled states; POST returns 202, or 200 for a current complete cache hit. Job GET and cancellation DELETE are owner-scoped, with cancellation returning 202. Repeated active clicks reuse one ID. Force against an already active identical key returns `AI_ACTIVE_JOB`; it never overwrites an in-flight row. Failed/cancelled retained jobs require explicit `force:true` for another attempt, rather than a blind paid retry.
- AI account/config serialization uses `users FOR NO KEY UPDATE`, not `FOR UPDATE`: it still excludes account deletion and competing account/config mutation, while remaining compatible with child foreign-key key-share checks made after article locks (first tag-counter buckets and retained annotation contexts). The article snapshot locks and source checks remain unchanged.
- A short PostgreSQL advisory transaction serializes admissions/claims. Maximum 128 queued/running jobs globally, 8 per owner; maximum 2 running claims globally and one per owner. Each process has at most 2 local worker tasks. Cancellation/config invalidation abort local sockets promptly or are observed by another process on its next heartbeat. **A provider may continue billing/computing a POST already accepted even after client cancellation.** During cancellation/lease loss a remote in-flight call can temporarily outlive its terminal DB status; the claim cap is not a provider-side exactly-once/billing guarantee. Bound the number of deployed worker replicas as well.
- Claims have a random fencing token and 120-second lease, checked before calls/checkpoints/publication. Heartbeats run every 2 seconds and do not resurrect expired leases. Each job has a 30-minute processing deadline. Call intent is committed before each POST; work is never requeued after an expired running lease, even if the provider outcome or database commit was ambiguous. The error is `AI_INTERRUPTED`; retry is an explicit user choice. A lost terminal commit cannot cause an automatic paid replay.
- Source/config freshness is checked under user/article locks before each call and final publication; changed config proactively invalidates active work. Cancelled/failed/stale workers cannot publish with an old lease token. Current-job GET hides stale output without altering permanent terminal rows; explicit historical GET retains access to original output. Article and annotation storage is read-only throughout this process.
- Input bounds: 2 Mi UTF-16 code units of selected HTML, 65,536 title units, 50,000 parsed nodes, nesting depth 100, 4,096 eligible segments. Individual text nodes are split losslessly at Unicode code-point boundaries into at most 1,200 UTF-16 units per segment. Every segment is included, including content after 14k; nothing silently takes a prefix. Batches contain at most 6,000 text units/32 segments. At most 512 provider calls/job; output at most 4 Mi translated text units / 8 Mi rendered HTML units. Exceeding a budget fails, never caches partial success.
- Translation requires every expected ID exactly once, no extras, nonempty bounded text, valid Unicode and a non-truncated completion. Progress is committed only after validating a complete batch. Missing/duplicate IDs, `finish_reason:length`, invalid JSON, refusal and partial responses fail closed.
- Summary sends every selected title/prose/caption/code segment through bounded leaf summaries, then reduces **all** leaf summaries until one remains (at most 8 reduction levels). Each response must list exactly all input IDs; reduction stages add to `totalChunks`, so the denominator can increase. `completedChunks/totalChunks` describe validated coverage, not token usage or semantic model-quality proof.
- Same-target translation skipping requires all-window language consensus, including short-title/tail checks; mixed/unknown content is processed. `franc` rankings are not confidence probabilities. See the provisional policy and hosted calibration limits below.
- Maintenance only recovers expired running leases in batches of at most 128. Admission counts only queued/running jobs through their partial index; history size never denies admission or triggers deletion. Point cache lookup uses `(user_id,cache_key,created_at DESC,id DESC)` over permanent history. Request/input/output/job limits are unchanged; permanent storage has no automatic terminal-row cap and can grow until the owner explicitly selects cleanup or removes the owning article/account.

Short AI database transactions set a 5-second lock timeout and 15-second statement timeout. Configure a database-wide statement timeout for standalone heartbeat/lease-recovery statements as well; the shared pool is application-managed. Configure an HTTP proxy timeout of at least 60 seconds for the explicit connectivity probe; article POST/GET/DELETE do not hold the browser request for job completion. Graceful termination must allow an HTTP call deadline plus database drain, and stop AI before closing the shared pool. A hard kill leaves lease-fenced interrupted work for the next worker, never an automatic retry.

## Language detection and provisional calibration

Language detection remains local to the API process and makes **no detector-provider call**. It uses the existing `franc@6.2.0` dependency with unrestricted language ranking, never an allowlist of the seven translation targets. An unsupported winner stays `unknown` rather than being forced to the nearest supported language. `francAll` normalizes ranked distances: the winner's score is 1, not a measured probability of correctness. Requiring a runner-up below 0.8 therefore does not establish 80% confidence and can reject ordinary English. The replacement **0.01 winner/runner-up separation is a provisional relative ambiguity guard**, not a calibrated confidence threshold or acceptance result. A tie, non-finite score or smaller separation vetoes skipping.

Every eligible segment, including titles and translated image/link metadata, is inspected. Sentence/newline/semicolon boundaries remain independent. Bounded sentences up to 480 UTF-16 units stay intact, avoiding the old artificial mid-word/short 240-unit remainder. Longer sentences use word-aware windows; an oversized unspaced token is split only at code-point boundaries. Final windows are not dropped or sampled away. Every letter must belong to the candidate's permitted scripts, including minority scripts that a dominant-script classifier could overlook; Japanese script extensions admit shared kana letters such as the prolonged-sound mark. Numbers, punctuation and emoji alone supply no language evidence.

At least one independently identified window of 40 letters is required as an anchor. A shorter fragment needs at least 12 letters, its **own unrestricted, separated supported winner**, agreement with the anchor, and agreement when ranked together with that bounded anchor. Context cannot override a contradictory, unsupported, tied or insufficient fragment. This applies equally to a title, caption, sentence or trailing window, regardless of its position; there is no hard-coded title vocabulary or fixture exception. Context samples contain at most two 480-unit windows, below the detector's input cap. Independently identified substantial windows in different supported languages return `mixed`; other uncertainty returns `unknown`. Both continue normal processing, not same-target skipping.

These rules deliberately retain conservative false negatives: very short headings, abbreviations, proper names, markup/split-node fragments and tiny final windows can still cause unnecessary translation. Rankings depend on sample length, subject matter and the model's language inventory. A same-script foreign phrase **inside** a longer window, borrowed words, related languages, transliteration or nonsense may still be misidentified despite complete input coverage; no statistical heuristic guarantees every code switch or guarantees absence of false skips. Han-only detection also does not prove a specific locale or distinguish Simplified from Traditional Chinese; `zh-CN` here is the existing supported target mapping. No universal language-quality or provider translation-quality claim is made.

`ai-language-fixture.ts` contains authored synthetic ordinary prose for all seven supported targets, positive and explicitly uncertain short headings/windows, unsupported Italian/Portuguese/Dutch/Russian/Arabic, and short foreign fragments. `ai-content.test.ts` retains the exact original English and all seven prose positives, bounded/long-window and trailing-fragment coverage, explicit ambiguity, same-script multilingual content, minority-script vetoes, and late-body/metadata cases beyond 14k. Late image fixtures use a valid archived `/api/assets/UUID`; image alt/title and link-title tests assert that the exact attribute text actually entered prepared segments **before** asserting its language veto. A positive English baseline prevents these negative witnesses from passing vacuously. The sanitizer is unchanged. The same-target PostgreSQL witness retains its original `skipped`/zero-provider-call assertion and the agreeing-title/foreign-fragment witnesses.

Development CI `43835630740` and its synthetic calibration records established the original English and PostgreSQL same-target skip regressions passing, but exposed three fixture/policy mismatches:

- The former French heading ranked unsupported `cat:1`, then `spa:0.903400`, `fra:0.902051`, although its body and a separately ranked combined sample favored French. It is retained verbatim as an **unknown** title/caption-with-French-body witness: unrestricted independent evidence must not be overridden by context. A distinct natural French heading supplies a new positive assertion; the French prose positive is unchanged.
- The complete library sentence returned `unknown` under production windowing. The old raw slice at 480 ranked unsupported `sco:1`, `eng:0.986762`; that raw slice was not proof of the exact word-aware production window. The full original sentence is retained as an explicit conservative-uncertainty negative, and a distinct longer museum sentence adds positive multi-window coverage. No window is dropped, rebalanced to conceal a tail, or forced from an unsupported winner into English.
- Src-less `<img alt=...>` was correctly removed by `cleanHtml`, so that purported foreign metadata never reached detection. The corrected archived-image fixtures and segment-presence assertions repair the witness rather than relaxing sanitization. Link-title metadata is covered too.

The replacement hosted-only diagnostic test calls `traceSyntheticAiLanguage`, which runs the **same inspection core** as normal detection. It reports actual production windows, independently agreeing/disagreeing fragments, the actual fragment+anchor rankings when reached, and the final decision/reason. Records contain only fixture labels, numeric segment/window positions and anchor references, character/letter counts, top-five ISO-code/score pairs and fixed decision/reason values—no text, segment IDs or keys. Unsupported independent evidence prevents a contextual ranking rather than silently being overridden; the trace makes that control flow explicit. Tests check traced/untraced equivalence, full-input letter accounting, bounded context and the trace field schema. There is no independent raw-slice ranking path. The trace helper refuses execution outside approved GitHub-hosted CI and must never be wired into article handling or production telemetry; normal detection does not log or collect traces.

Release validation must exercise the positive headings/windows, retained uncertainty negatives, real metadata coverage and source-shared traces. Historical development results do not replace the current release gate. Do not tune only to the original English regression, override unsupported winners, bypass infrastructure guards, or infer a general error rate from these small synthetic samples.
