# 批注与笔记

> 本页说明 0.2.0 的批注功能和验收边界；基础版 0.1.0 不包含这些能力。以实际部署版本为准。接口与数据类型分别见 [annotations-api.md](annotations-api.md) 和 `packages/shared/src/annotations.ts`。

## 阅读时使用

在自己的归档文章中打开 **批注与笔记**：

| 工具 | 用途 |
|---|---|
| 高亮 | 选中文字后标记引文 |
| 下划线 | 为所选引文添加直线 |
| 波浪线 | 为所选引文添加波浪线 |
| 备注 | 对选中文字添加纯文本备注，用 **保存备注** 确认；数据格式也允许不带引文的独立备注 |
| 钢笔 | 使用浏览器指针输入书写，保留设备实际提供的压力采样 |
| 荧光笔 | 半透明的手写笔迹；与文字“高亮”是不同的数据 |
| 橡皮 | 擦除命中的整条笔迹，而不是把原始笔迹切成碎片 |
| 撤销笔迹 / 重做笔迹 | 操作手写笔迹历史，不代表撤销服务器上的所有操作 |

工具只作用于活动文章的阅读正文，不能在导航、表单或批注工具栏上书写。恢复数据验证完成前不能开始绘制。切换文章、正文模式或账号时，旧的读取/保存回调不能覆盖新内容。手机上的工具应可触达、不产生横向页面溢出；墨水屏主题应维持清晰的边界与文字，避免动画和阴影。笔迹的原始颜色仍应保存在数据与导出中。

手写使用授权的 Apache-2.0 **WebInk 浏览器引擎**，集成修改与许可证随代码保留。普通鼠标不能证明压感支持；具体压力、合并采样和触控体验取决于浏览器与设备。这里不提供手写识别，不承诺 OCR 准确率，也不代表原生应用、原生宿主桥接或任何移动系统原生绘制能力。

## 文章、模式与版本

一份笔记属于 **账号 + 文章 + 正文模式 + 内容版本**。支持的批注模式是 `feed`（RSS 正文）和 `fulltext`（归档全文），不是嵌入的原网页。

- `contentHash` 是批注上下文的哈希，不应拿文章 API 的普通正文哈希直接替代。服务器根据清理后的正文、原始图片来源、文章来源 URL 和模式计算它；不同安装的图片 UUID 不应造成内容不匹配。
- 内容变更应保留旧的批注快照，不把旧引文悄悄移动到新正文。历史文档的保存不应替换文章最新正文。
- 显式选择已验证、属于当前账号的本机历史版本时，服务器若返回 `404` 或准确的 `409 ANNOTATION_CONTEXT`，仍可打开该缓存快照。待同步或冲突标识保持不变，不表示服务器已确认；其他错误不允许这种回退。编辑器在线读取时保留服务器上下文，以支持尚无首次修订的旧正文草稿后续保存；只读 MCP 不承担这个写入操作。
- 引文记录包含原文、前后文和位置提示。找不到或无法唯一定位的引文仍是笔记数据，必须提示未定位；不能以空列表表示“恢复成功”。
- 笔迹中的 URL 是文章的原始来源地址，不是当前应用的私有页面地址。导入的数据不能替换服务器已拥有的正文 HTML，也不能凭数据里的文章 ID 越权访问另一个账号。

## 保存状态：不要把“画出来了”当作“已同步”

应明确区分三个状态：

1. **未保存**：当前编辑尚未可靠写入本地存储，例如设备空间不足。不要直接关闭页面。
2. **本地待同步**：当前账号的专用草稿已保存在此设备，尚未得到服务器确认。联网前后都可能处于这个状态。
3. **已同步 / 已保存到服务器**：服务器已接受对应文章、模式、哈希与修订版本的写入。

普通页面、文章或正文模式切换会先暂停旧上下文编辑并等待最后一笔本机写入。写入失败则取消切换，保留当前草稿供导出或重试；不要关闭该页。重新载入相同正文版本或导入匹配 JSON 后，已有笔迹应继续显示并可继续书写。

保存期间的新编辑在前一轮成功后会继续自动同步；网络失败或冲突不会无限自动重试，需使用 **重试同步**、恢复联网或处理冲突。

升级到批注版本时，本机数据库会保留已有缓存并升级版本，防止旧阅读器标签页的退出/清缓存逻辑删除新笔记。如果提示旧标签页阻塞升级，请关闭其他旧版本标签页再重新载入，不要清除网站数据。

保存响应丢失后，客户端可以通过认证读取确认：只有同一上下文中更高修订的原始笔迹、文字标记与当前草稿完全相同，才按已经保存处理，不再发起覆盖写入。任何数据差异仍保留为冲突，不自动合并或盲目重设修订。

引擎收到输入或传输回调成功都不是服务器保存确认。网络失败、本地存储失败应可见并允许 **重试同步**；清理正文和图片缓存不能删除尚未同步的笔记。浏览器存储会被系统回收，本地待同步不是可靠备份。重要笔记请及时导出 JSON 并做服务器备份。

保存使用带引号的 `If-Match` 整数修订号。若另一设备已保存新版本，服务器返回 `412 ANNOTATION_CONFLICT`，不能按时间戳自动覆盖。保留本地草稿和服务器版本，显式处理冲突；单击重试不得盲目改用最新修订号覆盖对方。建议先导出本地草稿，再决定使用哪一份内容。

## 账号变化和共享设备

- 主动退出或切换账号时，有未同步笔记必须先说明风险，并提供 **导出未同步笔记**、**取消退出**、**放弃未同步更改**。放弃是明确的破坏性选择，不应由普通缓存清理隐式触发。
- 未同步或存储状态不可读时，也可以明确选择 **锁定笔记并退出**：隐藏账号内容，不删除草稿，并保留恢复保护。存储未确认落盘时，请保留当前标签页，不要刷新或关闭；必须由原账号重新通过服务器验证后恢复。若无法保存退出标记或取得认证协调锁，界面会说明服务器会话尚未撤销，不会绕过协调强行注销。
- 被迫失效的会话（例如服务器返回 401）采用 **锁定并恢复**：立即隐藏私人正文和笔记，隔离待同步草稿。不能靠旧的离线身份恢复阅读权限。
- 使用严格账号切换门禁：只要账号 A 仍有未解决的隔离笔记，账号 B 的登录就会在认证请求前被阻止，不能进入工作区，也不能读取、导出、重放或放弃 A 的笔记。只有 A 重新通过服务器认证后才能恢复草稿；A 同步 / 解决冲突，或明确选择 **放弃未同步更改** 后，才可退出并切换到 B。导出本身不等于已经解决待同步状态。
- 这不是对浏览器设备所有者的加密隔离。不要在不可信的共享设备上存储敏感笔记。

导出格式及恢复操作见 [notes-export.md](notes-export.md)，向 AI 客户端只读分享内容见 [mcp.md](mcp.md)。

## 验收与当前证据

`tests/e2e/annotations.spec.ts` 使用真实注册、RSS 抓取、归档图片、服务器写入和浏览器 UI，而不是仅给渲染器传一个成功夹具。内容来自 `tests/fixtures/upstream.mjs` 的自有中文文章和图片，新增笔记由 `tests/fixtures/annotation-fixtures.ts` 生成。

覆盖文字选择、四种文字标记、浏览器压感输入、整笔擦除/撤销/重做、页面重载与文章/模式切换、本地失败/离线/冲突、账号隔离恢复、JSON 匹配导入、Markdown 资源、真实 Chromium PDF 以及手机/墨水屏工具栏。压感事件是 Chromium CDP 的浏览器输入，不是直接调用引擎保存接口；不是物理笔设备认证。未实现的接口或 UI 应使相应用例失败，不能用跳过或虚假成功替代。

`apps/web/test/annotation-regressions.mjs` 另以受控客户端夹具覆盖批注会话验证 / Markdown 的 401 锁定、账号不匹配、导航写入屏障失败保留、同上下文笔迹重建、旧草稿精确回退及慢保存后的自动续传。夹具不替代真实后端验收。

[完整托管验证](https://github.com/Jasaxion/FeedInk/actions/runs/43724390424)已执行构建、单元/数据库、Chromium/WebKit 客户端及真实 API/E2E 门禁。测试文件存在或语法检查通过本身不是验收证据。发行页记录最终提交；诊断文件只供授权私下排查，不作为公共附件或发行资产。
