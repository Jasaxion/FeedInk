# FeedInk 1.0.0

## Scope

FeedInk is a self-hosted multi-user Web reader and installable PWA. It is not a native mobile or desktop application and does not claim private implementation or complete feature parity with any reference product.

This release combines:

- Reading-first subscription/folder/tag navigation, unread counts, search, saved items, progress, typography, speech and optional focus reading.
- Durable RSS bodies, separately captured full text, safe archived images, OPML and bounded portable archives, EPUB/mail workflows and paired operator backups.
- Selection-adjacent highlights, straight/wavy underlines and remarks; pressure-aware handwriting over the owned article reading area, independent black pen color, received-stroke retention, single-mark undo, and confirmed clear-all or handwriting-only actions scoped to the displayed body version.
- Account-scoped OpenAI-compatible AI configuration with authenticated credential encryption, explicit summaries and language-aware segmented bilingual translation. Results are retained until explicitly selected for cleanup; historical results do not silently replace a different current source.
- Read-only, authenticated, scoped MCP article/note/image tools.
- Exact PostgreSQL count projections, additive literal-search indexes, default filesystem hash fanout and optional private S3-compatible storage, with verified restartable copies and bounded-memory referenced-blob recovery.

## Docker deployment

Use the repository's `Dockerfile`, `compose.yaml`, and `.env.example`:

1. Copy `.env.example` to private `.env`, set independent database/session secrets and the browser-visible `APP_URL`.
2. If enabling AI, generate a separate stable 32-byte base64 `AI_ENCRYPTION_KEY`. Do not use a provider key or the session secret for this purpose. Keep this key with private deployment recovery material.
3. Build the image, start PostgreSQL, run the documented one-off administrator bootstrap with a private password on stdin, then start the app.
4. Use HTTPS for remote browser/PWA access. The application binds to loopback by default; PostgreSQL has no published port.

See [deployment](../deployment.md) for exact commands and reverse-proxy configuration. S3 remains optional; its bucket, endpoint and credentials are operator settings, never public per-request destinations. A writable, pre-provisioned `/data` root is still required for the durable journal.

## Upgrade and recovery

- Production operators must stop all writers and keep a verified matching PostgreSQL/blob backup before migration. A disposable development preview's reset policy is not a production retention policy.
- Do not edit applied migration checksums. New indexes require the server's `pg_trgm` support and a maintenance window; existing extension namespaces are preserved.
- Filesystem reads retain legacy flat blobs. New writes use hash fanout. Older binaries do not understand every new placement or storage layout; rolling back after writes requires the documented matching-data procedure, not merely changing an image tag.
- Paired referenced-blob bundles retain database rows, note contexts and referenced bytes. They are not arbitrary-volume copies and do not include the separate AI encryption key, browser-local drafts, unrelated files or all historical S3 object versions.
- Portable user ZIP/EPUB exports stay intentionally bounded; they are not a million-article operator backup mechanism.

## Verification and limits

The final release page records its tag, CI run and measured scale evidence. A development preview artifact verifies code-build integrity only; it is not a release acceptance result.

Synthetic database measurements identify hardware, dataset size, exact-count checks, limits and index/write costs. They do not certify every corpus, cold cache, storage provider, network or sustained workload. Broad/short literal searches necessarily have exact-count costs. Browser pen witnesses do not certify every physical stylus or e-ink device. Statistical language detection can remain uncertain, and validated segment coverage is not a guarantee of semantic model quality. Cancellation cannot reverse provider work already accepted and billed.

See [testing](../testing.md), [AI security](../ai-security.md), [storage](../storage.md), [backup](../backup.md), and [notes export](../notes-export.md) for the detailed boundaries. Preserve actionable save/conflict/recovery notices; normal verified-region placement is not displayed as an error.
