# FeedInk 0.2.0 — 批注、手写与只读 AI 接口

> 发行记录。请使用对应发布标签；GitHub Release 记录最终提交和 CI。开发分支的后续改动不自动属于此发行版。

## 新增能力

- 阅读器内的文字高亮、直线下划线、波浪线和纯文本备注。
- 基于 Apache-2.0 WebInk 浏览器引擎的压感钢笔、荧光笔、整笔橡皮、撤销和重做；不依赖 Android 宿主或原生应用外壳。
- 按账号、文章、RSS/全文模式及正文哈希隔离笔记，保留已验证的历史正文上下文。
- 本机草稿、服务器确认与版本冲突状态分离。失效会话或存储故障可以非破坏性锁定；原账号验证后恢复，另一账号不能读取或重放未解决草稿。
- 可恢复的原始 JSON、含相对 PNG 资源及原始 JSON 的 Markdown ZIP，以及保留引文、备注、原始/未定位笔迹的打印报告。
- 第三版文章存档保留笔记和上下文，兼容旧版导入；重复恢复不会静默覆盖不同笔记，可修复缺失的归档图片。
- 标准 Streamable HTTP MCP：七个只读文章、笔记、搜索和图片/笔迹预览工具；独立的 `articles:read` / `notes:read` 范围，一次性令牌展示、哈希存储、到期和撤销控制。

## 升级注意

1. 按 [备份说明](../backup.md) 成对备份 PostgreSQL 与文件卷，再升级代码/镜像。不要把 `.env`、数据库、笔记或令牌加入仓库。
2. 服务启动会执行新增的笔记、令牌和上下文迁移。保留部署密钥与持久卷，不要用重建数据库代替升级。
3. 浏览器私有数据库升级到版本 3，保留原有缓存，同时防止旧阅读器标签页清掉新笔记。如果提示旧标签页占用，请关闭旧标签页后重新载入；不要清除网站数据。
4. 未同步草稿不属于服务器 ZIP 备份。先同步或另存 JSON；存储故障时保留当前标签页，尤其不要丢失尚未落盘的笔迹。
5. MCP 默认使用 HTTPS。Docker 反向代理应配置正确 `APP_URL` 和精确的 `TRUST_PROXY`；直接回环开发例外不能套用于任意网桥或公网 HTTP。演示账号不能创建 MCP 令牌。

如需回滚，先保存新增笔记，再按旧版本与配对备份的恢复步骤操作。旧客户端不理解新的笔记与本机存储格式，不能依靠清缓存强行降级。

## 数据和平台边界

- JSON 是原始恢复格式；PNG/PDF 展示结果不能替代压感、锚点和完整笔迹数据。
- 原始/未定位预览不等于已准确贴到当前正文。超过明确的渲染预算时拒绝不完整导出，不悄悄省略后续笔迹。
- 文章正文、图片字节与笔记上下文哈希有不同含义，不可互换。
- 笔记搜索覆盖文字与引文，不提供手写 OCR。
- 交付仍为 Web 与可安装 PWA，不包含原生平台安装包。浏览器打印、安装、触控与手写硬件能力不同，受控浏览器测试不代表所有实体墨水屏或笔设备都已验证。
